# 基礎錯誤檢查表

只套用變更檔案實際使用的語言與框架，並沿變更介面的直接資料流檢查呼叫端與被呼叫端。每一項都必須能連到目前 diff 的直接失敗路徑，才可列為問題。

## 通用

- 條件判斷、布林運算子或空值處理是否讓分支走反。
- 函式呼叫、匯入、屬性存取與回傳值的名稱、參數或資料形狀是否對得上既有介面。
- 新增、移除或改名的公開值是否仍被直接呼叫端與直接被呼叫端正確使用。
- 資料流上的空值、空集合、找不到資料、失敗回應、例外與非同步拒絕是否被正確處理。
- 寫入、刪除或更新流程是否明確處理成功與失敗結果。

## 可從字面確認的資安問題

- 使用外部輸入以字串串接、插值或格式化方式建立 raw SQL，且沒有使用參數綁定。
- 使用外部輸入建立 shell command、檔案路徑或系統呼叫，且沒有可確認的限制或跳脫。
- 將外部輸入未跳脫地寫進 HTML、DOM 或等效的 raw output API。
- 程式碼中直接寫入可用的憑證時，除下列例外外要回報；回報時只指出位置與用途，不得輸出憑證值：
  - 前端專案的 `.env` 與 `.env.*` 檔案。
  - 後端錯誤處理流程中，傳送錯誤資訊到 Google Chat 的 URL，即使 URL 包含憑證。

## JavaScript / TypeScript

- `await`、Promise 回傳與錯誤處理是否維持原本的執行順序。
- `null`、`undefined`、`false`、`0` 與空字串是否被錯當成同一種狀態。
- 變更後的參數、物件屬性、陣列元素與函式回傳型別是否相容。
- 共用物件、函式參數或 state 是否被意外原地修改，導致後續流程拿到錯誤值。

## Vue 3

- template 使用的狀態、方法與事件處理器是否在元件中存在，且參數相符。
- props、emits 與父子元件傳遞的名稱及 payload 是否一致。
- script 中的 `ref` 與 `reactive` 存取方式是否正確；template 是否維持 Vue 的自動解包語意。
- props 是否被直接修改，或副作用是否在不正確的生命週期執行而導致畫面或資料不同步。

## Laravel / PHP

- route、controller action、request 資料與 route model binding 的參數名稱及型別是否一致。
- Eloquent 查詢回傳的單筆 model、collection、boolean 或受影響筆數是否被正確處理。
- 新增或修改的資料寫入流程是否沿用可見的 validation 與 authorization 路徑。
- 關聯、nullable 欄位與交易結果是否可能被錯誤存取或忽略。

## Python

- 可變預設參數、值比較與身分比較是否會產生意外共用狀態或錯誤分支。
- coroutine 是否有正確 `await`，同步與非同步呼叫是否相容。
- iterator、generator、檔案或連線資源是否在仍需使用時被耗盡、關閉或重複消費。
- 函式的回傳值、例外處理與可選值是否符合呼叫端預期。
