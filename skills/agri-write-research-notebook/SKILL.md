# 撰寫研發紀錄簿

1. 一開始先詢問使用者要用「條列式」還是「段落式」，取得選擇後再撰寫或續寫；不要自行預設模式。若使用者同時指定工作項目與模式，直接採用已明確指定的模式，不重複詢問。
2. 確認工作項目名稱、詳細說明及要產生的頁數。先從使用者提供的資料或專案內計劃書找名稱與說明；缺少的資訊再一起詢問。沒有依據的進度、成果或數字不要編造。
3. 安排每頁主題，讓各頁依開發脈絡推進，避免重複。撰寫前讀取 [寫作規則](references/寫作規則.md)，依共通規則與所選模式逐頁修稿。
4. 依所選模式撰寫：
   - **條列式**：每寫一頁前執行一次 `node scripts/counts.mjs`；輸出的 `first_level` 是該頁第一層編號項目數，`second_level` 依序對應每個編號項目下的第二層項目符號數。按回傳數量撰寫，不自行固定各頁或各段數量。第一層各用簡短標題說明重點，第二層寫詳細說明。每個編號項目的文字少於 200 字；只用文字，不放圖片、表格或程式碼區塊。口吻要像開發時隨手記下的內容。
   - **段落式**：每頁保留能辨識主題的 Markdown 標題，正文寫成數個分開的自然段落，不使用編號或項目符號，也不執行 `scripts/counts.mjs`。每段只談一個重點，約 130～180 字；按內容需要安排段數，通常為 3～4 段，不為湊字數重述。以陳述式說明問題、資料的角色、處理方式、判斷條件與理由；用「整理資料時……」「是否適用取決於……」等通則句描述尚未執行的工作，不把計畫改寫成已完成的成果，也不以「預計」「目前尚未取得」「下一步」反覆交代進度。保留來源中的範圍、條件、可能性與限制，但不要憑空補出測試結果或具體成效。既有 `reports/` 段落式文章可作語氣與篇幅參考，不當作新工作項目的事實來源。
5. 逐頁存成 `./reports/<工作項目名稱>-<頁碼>.md`，頁碼只填阿拉伯數字（例如 `-1.md`）；未指定起始頁碼時從第 1 頁開始。遇到同名檔案，先確認要接續或改寫，不直接覆蓋；使用者已明確要求改寫指定檔案時不重複詢問。完成前逐頁檢查頁數、段落或項目數、字數、格式與內容是否符合來源及所選模式。
